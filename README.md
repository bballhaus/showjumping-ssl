# Predicting Showjumping Outcomes with Self-Supervised Video Representations

CS 131 final project (Stanford, Spring 2026) — Brooke Ballhaus, `ballhaus@stanford.edu`.

Pipeline: scrape 1.50 m showjumping broadcasts from YouTube → cut into 2-second clips → YOLOv8 horse-presence filter → hand-annotate fence boxes → recover takeoff distance `d` from pole-length geometry → self-supervised pretrain an R(2+1)D-18 video encoder (InfoNCE + temporal-order) → fine-tune small heads for outcome classification and `d` regression.

## Reproducing the milestone

The full pipeline is wired into [`notebooks/colab_milestone.ipynb`](notebooks/colab_milestone.ipynb). Open it in Colab Pro, point `GITHUB_REPO` and `DRIVE_DATA_ROOT` at your fork in cell 0, and run cells top to bottom. Each section saves intermediate outputs (downloaded videos, segmented clips, YOLO-filtered subset, annotations, embeddings, figures) to your Google Drive so they persist across Colab sessions.

**Highlights:**
- Cell 0 clones this repo into `/content/project` and symlinks `data/` + `checkpoints/` to Drive — code stays fresh from GitHub, data persists.
- Cell 3 launches an inline matplotlib + ipywidgets annotator with a frame scrubber (broadcast cameras track the horse, not the fence).
- Cell 5 trains the SSL encoder. If retrieval in cell 7 shows collapse (NN similarities ≈ 0.97), cell 7b executes the proposal's planned Kinetics-400 fallback.
- Cell 8 produces all five milestone figures including a t-SNE colored by source video that exposes the venue-clustering bottleneck.

**Recommended runtime:** A100 (~10 min for SSL training). L4 also fits batch 16. T4 (16 GB) works but drop `batch_size` to 4 in cell 5.

## Running pieces locally

If you only want to use individual modules without the notebook:

```bash
pip install -r requirements.txt           # do NOT add torch -- Colab/CUDA wheels would be replaced

python -m src.data.scrape       --out data/raw                         # yt-dlp + ffmpeg
python -m src.data.segment      --raw data/raw --out data/clips        # 2-second cuts, stride configurable
python -m src.data.filter_clips --clips data/clips --device cuda       # YOLO horse-presence filter
python -m src.preprocess.annotate --clips data/clips                   # OpenCV annotator (laptop only, needs display)
python -m src.preprocess.run_pipeline --clips data/clips \
    --fences data/annotations/fences.csv --out data/annotations/auto.csv --device cuda
python -m src.ssl.train         --clips data/clips --out checkpoints   # joint InfoNCE + order pretraining
python -m src.ssl.embed         --clips data/clips --ckpt checkpoints/encoder.pt --out data/embeddings.npz
python -m src.viz.make_figures  --csv data/annotations/auto.csv --emb data/embeddings.npz \
    --log checkpoints/train_log.csv --out milestone/figures
```

## Week 3–4: venue fix, automated detection, downstream, baselines, analysis

The week-3/4 work — outcome labels, the SSL venue fix, automated fence detection,
the downstream heads, the three baselines, and the sample-efficiency / ablation
analysis — runs as follows (all Colab-friendly; `--device cuda`):

```bash
# 1. Automated fence detection (recovers the proposal's YOLO path).
python -m src.preprocess.fence_yolo export --clips data/clips --fences data/annotations/fences.csv \
    --out data/fence_yolo
python -m src.preprocess.fence_yolo train  --data data/fence_yolo/dataset.yaml --epochs 100 --device 0
python -m src.preprocess.fence_type_cnn train --clips data/clips \
    --fences data/annotations/fences.csv --out checkpoints/fence_type.pt    # vertical-vs-oxer CNN

# 2. SSL re-run with the venue-confound fixes (milestone's key bottleneck).
python -m src.ssl.train --clips data/clips --out checkpoints --kinetics-init \
    --balance-venues --lambda-domain 0.3                                    # balanced sampler + DANN head

# 3. Outcome labels -> merged downstream label table.
#    (run OutcomeAnnotator in Colab to produce data/annotations/outcomes.csv first)
python -m src.data.labels --auto data/annotations/auto.csv \
    --outcomes data/annotations/outcomes.csv --by-video data/annotations/by_video.csv \
    --out data/annotations/labels.csv

# 4. Downstream heads + the three baselines (outcome classifier + d regressor).
python -m src.downstream.train       --labels data/annotations/labels.csv --clips data/clips \
    --ckpt checkpoints/encoder.pt --group-by-venue
python -m src.baselines.from_scratch --labels data/annotations/labels.csv --clips data/clips
python -m src.baselines.imagenet2d   --labels data/annotations/labels.csv --clips data/clips
python -m src.baselines.type_logreg  --labels data/annotations/labels.csv

# 5. Analysis: sample-efficiency sweep, ablations, then all figures.
python -m src.eval.sample_efficiency --labels data/annotations/labels.csv --clips data/clips \
    --ckpt checkpoints/encoder.pt --out data/results/sample_efficiency.csv
python -m src.eval.ablations --labels data/annotations/labels.csv --clips data/clips \
    --type-ckpt checkpoints/encoder.pt --ckpts both=checkpoints/encoder.pt info_only=checkpoints/info_only.pt
python -m src.viz.make_figures --csv data/annotations/auto.csv --labels data/annotations/labels.csv \
    --emb data/embeddings.npz --log checkpoints/train_log.csv \
    --results data/results/sample_efficiency.csv --out milestone/figures
```

`--group-by-venue` holds out entire source videos for validation — the honest
cross-venue test the milestone calls for. Drop it for the easier stratified split.
